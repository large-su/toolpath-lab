# ToolpathLab

> English: [README.en.md](README.en.md)（中文是主文档，英文版手工同步） · 刀路规划基座

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Python 3.10+](https://img.shields.io/badge/Python-3.10%2B-blue.svg)](https://www.python.org/)

ToolpathLab 是一个 2.5D 刀路规划基座：给定一把刀具和一块加工区域（9 种规则形状，其中「球冠」的上表面
是曲面、「圆环」带一个**岛屿**（孔）；或从 DXF 图纸导入的轮廓，图里的其余轮廓也能一键当岛屿），
用栅格 / 环切 / 螺旋环切 / 自适应环切生成刀路，在三维窗口里显示工件、刀路、刀具与**按切深着色的
已加工地面**，按进给速度播放加工过程（可让地面随播放**渐进显示**），并给出覆盖率、2.5D 材料切除、
刀柄碰撞检查，以及自述式的 NC / CSV 导出。

后端是纯 Python（只依赖 numpy），前端是原生 ES 模块加 three.js，桌面窗口由 Electron 提供。
刀具与区域都用参数描述，参数面板根据后端的参数声明自动生成。

## 功能

- **刀具**：平底刀，可设置直径与长度。刀具在加工面上的足迹半径决定刀路相对区域轮廓的偏置量。
- **区域**：方形（边长）、矩形（宽 × 高）、圆形（直径）、椭圆（长 / 短半轴）、
  U 形（外宽 / 外高 / 壁厚）、哑铃形（两端方头 + 细颈）、三角形（底边 × 高，顶角可调尖），
  都以原点为中心，加工面为 XY 平面。另有**导入轮廓**，见下一条。
- **图纸导入**：在界面里选一张 DXF 图纸，后端读出其中的闭合轮廓（`LWPOLYLINE`、`POLYLINE` 与
  首尾相连的 `LINE`），再从轮廓下拉里选中一条当作加工区域。**圆弧/圆默认仍然"不猜"**——如实列进
  「跳过项」并给出中文提醒；想读它们就把「圆弧弦高容差」给成 0 以上的值（界面「区域」一节里就有这
  一项，`/api/catalog` 的 `import` 一节发布同一个声明），`ARC` / `CIRCLE` / `ELLIPSE` 会按**每段弓高
  不超过容差**折线化，段数由弧自身半径算出（`段数 = 扫角 / (2·acos(1 − 容差/半径))`，单条曲线最多
  `2048` 段），响应里会回显参数并报出折线化了哪些图元、多少点。样条（`SPLINE`）无论给不给容差都
  仍然跳过：NURBS 的权重与节点是另一个量级的事情，这条边界宁可不猜。导入的轮廓**刻意不注册**进
  能力目录——界面只有在真的导入过文件之后才会在形状下拉里多出「导入轮廓」一项，点串随规划请求
  一起发给后端；导出的 NC 头部只写 `imported - N points`，不会把上千个点打印进文件。
- **刀路**：
  - **往复 Zigzag**：奇数刀反向，相邻两刀在端头直接连过去；
  - **单向 One-way**：每刀同向，刀与刀之间抬刀到安全面再回到起点；
  - **环切 Contour**：从区域轮廓逐圈向内偏置（等距轮廓），相邻环方向可切换（交替 / 全顺铣 /
    全逆铣）；凹形状的细颈被偏置吃掉后一层会分裂成多条环，互不相连的环之间自动抬刀快移，
    套在里面的环之间直接过渡。**区域带岛屿时**刀路从两侧同时逼近：轮廓环向内、岛屿环向外，
    每一条环只保留"离自己那侧更近"的一半（中缝规则），所以带宽被两侧均匀切掉，而不是只从外面
    一圈圈挤进去、把岛边留一大圈；两族环在中线附近收束（中线附近两族可能略有重叠，属于可接受的
    重复走刀，换来的是一整条带都被覆盖到）；被裁开的环是**开口段**而不是闭环（闭合会横穿岛屿），
    段之间的连接要么贴着材料走、要么抬刀快移——连接线会先做"离岛距离"检查，不会连穿岛屿。
  - **螺旋环切 Spiral**：**同一层一条连续刀路**。每走一圈就向内进一个切宽（一圈之内从当前等距
    线过渡到下一条），因此**层内不抬刀、也没有连接段**；最外圈仍先整圈走完（螺旋只在外圈起点
    碰它一次，不整圈走会留下壁边一条），之后一路螺旋到中心。凹形的兄弟环之间无法连续过渡，
    仍然抬刀。**带岛屿时它会交给环切**（绕岛的一圈必须被裁开、两侧反向，那已经不是一个螺旋了）
    并在「刀路说明」里说明；**适用范围是"单面进刀"的形状**：薄壁、U 形、哑铃这类材料**两侧同时
    进刀**的形状，环切每圈两面一起推进，而螺旋一圈只从一面进刀，会把壁中间留成一条未切带——
    规划器**自己量覆盖率**（对比同一形状的环切），掉超过 2 个百分点就**回退成环切**并在
    「刀路说明」里写明原因，不会默默给出更差的刀路。
  - **自适应环切 Adaptive**：环切 + 覆盖率闭环。用请求的切宽算一遍、量一下覆盖率，没到
    「目标覆盖率」就按「收紧系数」收窄重算（默认最多 3 轮，切宽收到「切宽下限」为止），
    最后返回覆盖率**最好**的那一次；同时守「工时上限」——收窄切宽靠的是多走几圈，太贵的那一轮
    不采用。到不了目标时提醒"要达标得多花多少时间"或"收到多少就不再提升"（后者往往是刀具
    几何的极限：圆刀切不到尖角）。
- **刀具**：平底刀、球头刀、圆鼻刀（直径、长度，圆鼻刀另有角半径 Rc，都是参数）。贴壁间隙取
  **整段切深的外伸半径**，所以球头/圆鼻刀在最后一层也不会啃到壁（`Rc` 之内外伸半径从 `R−Rc` 长到
  `R`）；覆盖率按底面**足迹**算：平底刀是整个半径、圆鼻刀是 `R−Rc` 的圆面、球头刀是一个点
  （覆盖率是**平面**问题，问的是"刀有没有经过"；材料被切掉多少由下面的高度图按**刀具截面轮廓**
  回答）。
- **锥度刀**（`taper_angle_deg`，锥度半角，默认 0 = 直壁）：刀刃侧面每侧的张开角度，直径指**刀尖**
  处，往上每毫米长 `tan(锥度)` 的半径。锥面会一起进贴壁间隙——切深越大让得越多，所以锥度刀在深腔里
  不是矛盾：刀路整体被推到 `R + (切深 − Rc)·tan(锥度)` 之外，锥面自己不会啃壁（有测试用"刀路到壁
  的距离 = 解析值"钉住）。三维里画的锥面与这个公式是同一份几何。
- **刀具库**：界面「刀具」一节顶部有「预设」下拉，内置 6 把常用刀（平底 D6 / D10、球头 D6、圆鼻 D10 Rc2、
  锥度 15°、细小 D3），选一项就把它的参数填进下面**同一组字段**。预设是**快捷方式，不是第二套配置
  系统**：改动任一数值就回到「自定义」，两种情况下发给接口的请求完全一样（有测试断言请求里不带库的字段）。
- **刀柄碰撞检查**：刀具被建模成两段——刀刃（半径 R、高 `flute_length_mm`，锥度刀就是**锥面**）与
  它上面的刀柄（半径 `shank_diameter_mm / 2`），这也正是三维里画出来的形状（默认规则
  `min(0.65 L, 6 R)` 与 `1.25 R` 就是前端一直在画的那把刀，现在由后端给出数值，画的和检查的是同一份
  几何）。切深超过刀刃长度后刀柄就进了型腔：它需要 `刀柄半径` 那么宽的壁边空间，而策略只保证**刀刃**
  自己的贴壁间隙，所以刀柄比刀刃粗时会**报碰撞**（提醒里给出最近处离壁多少、差多少，以及三条出路）；
  最深切深超过刀具长度则提示"夹头会伸进工件"。检查结果随响应给出（`holder` 块，含型腔里最宽处与
  最紧处余量），统计面板在刀柄进入型腔时多一行「刀柄间隙」。两个刻意不查的地方：**进刀段**不查
  （斜坡/螺旋允许走出区域，那由「刀路说明」负责），**区域外的点**不算（那不在型腔里）。
- **参数**：切宽、走刀方向角、进给速度、安全高度、快移速度、**拐角减速**；栅格策略另有
  **边界处理方式**与**边界余量**。控件由后端的参数声明自动生成，见[参数与固定值](#参数与固定值)。
- **拐角减速**：切削段转角超过「拐角减速起始角」时，进给按转角线性降到「拐角最低进给」
  （180° 折返处降到该比例）。环切的多边形角、小半径环的折线角都会被降速，圆滑曲线不受影响；
  刀路被切成若干段等进给的移动，几何与刀轨数不变，只有进给、预计工时与播放速度会变。
  默认关闭（起始角 0°），打开方式见[参数与固定值](#参数与固定值)。
- **分层深度**：给出「总深度」与「吃刀深度」后，同一条 XY 路径会**逐层下移**（最后一层取剩余量，
  不会超过总深度），得到平底型腔的多层刀路。每层的切削与连接都落在该层深度上，抬刀仍回到上表面
  之上的安全高度；刀轨数与切削长度按层数增加，三维里工件会转为半透明，好看见里面的层。
  默认关闭（总深度 0 mm）。
- **三维视图**：工件实体、区域轮廓、刀路（切削 / 连接 / 快移分色，切削段再按进给分色：开了拐角减速
  后，被降速的段用更暖的颜色单独画出）、**刀具实体（刀头按刀具类型给出真实轮廓：平底、球头半球、
  圆鼻的圆角 Rc 都画出来）**、已走轨迹、**按切深着色的已加工地面**（见「分析」）、实时阴影；
  分层切削时工件转半透明。
- **播放**：按每段运动自己的进给速度做时间参数化，支持播放 / 暂停、拖动进度，并给出切削长度与预计工时。
- **导出**：NC 程序（G-code，G21 / G90 / G17 加 G0 / G1 带 F）与 **CSV 点表**（一个刀点一行，
  可直接丢进 Excel / pandas）；界面上的「导出 NC」与「导出 CSV」会**把这条刀路的来历一起写进
  文件**——NC 头部依次是程序名、请求参数回显、刀路摘要（策略 / 刀轨数 / 刀点数 / 切削与快移长度 /
  预计工时）、覆盖率与提醒、以及策略自己的说明（自适应环切的性价比曲线、拐角减速的说明都在这里）；
  CSV 用 `#` 注释块带上同样的事实，数据行仍是纯 ASCII，`pandas.read_csv(path, comment="#")`
  即可跳过。接口见下表。
- **分析**：**覆盖率**——用网格比对"刀具扫过的面积"与区域面积，给出覆盖率、未切除面积与
  未切除连通块的位置，并在三维里用警示色**叠出未切除的区域**（左侧「显示」里可关掉）；
  漏切较多时（默认超过 2%）随响应给出提醒。**区域带岛屿时，"区域"就是外轮廓减去岛屿**：岛屿那块
  料是要留下的，所以既不算已切也不报未切（三维里它还会把工件挖成孔）；刀路绕岛的最近距离也有
  测试钉住（刀心离岛 ≥ 刀具半径）。**材料切除（2.5D 高度图）**——每个格子记录被切到
  的 Z，给出**到面率**（达到目标地面的格子占比，即按深度的覆盖率）、切除体积、剩余余量与完全
  没碰过的面积；到面率低于 90% 时同样给出提醒，统计面板里相应多出「到面率 / 切除体积 /
  剩余余量」。**扫掠的是刀具自己的截面轮廓**，不是一片平底圆盘：球头刀按 `z + R − √(R²−d²)`
  在离轴 `d` 处抬起（网格上真的出现弧形沟槽），圆鼻刀是 `R−Rc` 的平底加角圆弧，平底/锥度刀
  保持平底（锥面只参与贴壁间隙）。于是**刀间残留高度**是算出来的而不是假设的：相邻两刀之间
  （距刀轴各 `s/2`）的理论脊高 `h = 截面在 s/2 处高出刀尖的高度`——球头刀就是经典公式
  `h = R − √(R² − (s/2)²)`，写进「刀路说明」，也随响应发出（统计面板的「刀间残留」）；`h` 超过
  这一层的切深说明两刀之间根本清不到底，会明确提醒把切宽降到 `2R` 以下。**到面率的容差就是这条
  脊**：弧面底面天然是波浪形，不会因为"只有沟槽最低点才算到面"而误报（平底刀的脊是 0，数字与
  以前完全一致）。
  **已加工地面**——同一份高度图会**降采样后随响应发出**（最多 4096 格，每格取块内**最深**的一次
  切削，即"刀在这里到过多深"；区域外的格子留空），三维视图把它按切深从青到橙着色、按真实 Z
  画成地面，所以分层铣出的台阶与球头的沟槽一眼可见（左侧「显示」里的「切深」）。降采样只影响
  这一层显示：覆盖率、到面率与各种体积始终按 0.5 mm 的测量网格算。
  **播放联动（渐进切深）**——同一份高度图还会**随响应带 8 张"到某一步为止"的快照**（每张按 1024 格
  降采样、用的是完整地面的色标，并标出它覆盖到第几个移动）。打开「显示」里的**渐进切深**后，
  「切深」地面就跟着播放条走：拖动或播放时只画出到当前位置已经切掉的材料（起点为空，因为确实还
  没切；走到最后一个切削移动后切回完整分辨率的地面）。快照是**在同一次扫掠里顺手拍的**（每次只是
  一次块归约），所以联动几乎不花时间；播放时只在快照变化的那一帧重建几何，不会每帧重画。
- **闭环**：**自适应环切**策略——先用请求的切宽算一遍、量一下覆盖率，没到目标就自动收窄
  重算（默认最多 3 轮），同时守住工时上限，返回覆盖率与工时都合适的那一次；到不了目标就
  如实说明"要达标得多花多少时间"或"收到多少就不再提升"。每一轮的切宽、覆盖率、环数、
  切削长度与工时都写在「刀路说明」里，就是一条性价比曲线。
- **HTTP 接口**：能力目录、规划、导出三个接口，便于脚本调用与集成。

## 界面

左侧是参数面板，右侧是三维视图、统计与播放条。

| 鼠标操作 | 功能 |
| --- | --- |
| 左键拖动 | 旋转视角 |
| 中键滚轮 | 缩放 |
| 右键拖动 | 平移 |

- **区域**（参数面板上部）：形状下拉与对应参数；选一张 DXF 图纸后，形状下拉里会多出「导入轮廓」
  并自动选中，下面再出现轮廓下拉（图纸里有几条闭合轮廓就列几条）与**「其余 N 条轮廓作为岛屿」**
  开关——勾上就把当前轮廓当型腔、其余轮廓当**岛屿（孔）**：刀路绕开它们，覆盖率与切除仿真也不再
  把它们算成未切除的料（一张"型腔里有个凸台"的图纸正好是两条轮廓）。「圆弧弦高容差」也在这一节：
  0 表示圆弧/圆照旧只报告不近似，给正值就按它折线化（控件由 `/api/catalog` 的 `import` 一节生成，
  和规划参数同一套声明）。
  **「圆环」是内置的岛屿形状**（圆型腔 + 中心圆岛），带宽 `(D−d)/2` 是解析的，用来验证"绕岛屿"。
  **「球冠」是唯一上表面不是平面的形状**（圆底 + 过边缘的球冠上表面）：刀路依旧按恒定 Z 等高分层走
  （所以曲面上方的层会先切空气，notes 里会说明），但**切除体积、高度图与三维显示都从这个曲面起算**
  ——工件的顶面按 `top_map` 画出来，毛坯多出来的那部分球冠也是真正要切掉的料
  （体积 = 圆柱 + `πh²(3Rc−h)/3`，有解析测试钉住）。
- **刀具**（参数面板最上部）：预设下拉 + 参数；选一个预设即填入它的参数，改任何一个数值就回到「自定义」。
- **视图工具条**（顶部居中）：最佳 / 前 / 后 / 左 / 右 / 上 / 下；再次点击当前方向会切换到对面。
- **外观开关**（左上角）：实时阴影、白色背景、网格地面。
- **显示开关**（参数面板底部）：工件 / 刀路 / 快移 / 已走轨迹 / **未切除** / **切深** /
  **渐进切深** / 刀具逐项开关；
  其中"未切除"是覆盖率分析标出来的漏切区域（半透明警示色叠在工件上），"切深"是按切深着色、
  按真实 Z 画在工件内部的已加工地面（分层铣时台阶可见；点前的渐变色块就是它的色带）。
- **播放条**（底部）：播放 / 暂停（空格键同样有效）、回到起点、拖动进度、当前时间。
- **统计面板**（右上角）：区域尺寸、刀轨条数、刀点数量、切削长度、预计工时、覆盖率与未切除面积；
  刀柄进入型腔时多一行「刀柄间隙」（离壁还剩多少，差多少）；
  底下还有可展开的**「刀路说明」**（后端策略写的过程信息：环数/层数、环绕向、自适应各轮的
  性价比曲线、**斜坡/螺旋的进刀段长度**、刀柄余量等），默认收起。进刀说明同时会写进导出的 NC 头部与
  CSV 注释块——斜坡是切削移动，1° 下切 2 mm 就是 114.6 mm 的引入段，长度不该等到上机床才发现。

![俯视图](docs/images/screenshot-top.png)

参数面板由后端 `/api/catalog` 返回的参数声明生成：新增区域形状或刀路策略后，
界面上会自动出现对应的控件，不需要修改前端代码。**唯一的例外是「导入轮廓」**：它的几何是
随请求给出的点串而不是参数，因此刻意不在目录里，界面只在真的导入过图纸之后自己加上这一项。

## 使用

### 脚本调用

```bash
python examples/headless_plan.py
```

该示例不使用界面，直接生成一条刀路、打印统计信息并导出 NC 文件，
可以当作把 ToolpathLab 当作库使用的起点：

```python
from toolpath_lab.core.region import build_region
from toolpath_lab.core.tool import Tool, ToolKind
from toolpath_lab.planning import run_plan

outcome = run_plan(
    planner_id="raster",
    tool=Tool(ToolKind.FLAT, diameter_mm=6.0, length_mm=30.0),
    region=build_region("square", {"side_mm": 80.0}),
    parameters={"mode": "zigzag", "stepover_mm": 6.0, "feed_mm_per_min": 800.0},
)
print(outcome.toolpath.statistics())
```

### HTTP 接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/health` | 健康检查与版本号 |
| `GET /api/catalog` | 能力目录：区域形状、刀路策略、参数声明与默认值 |
| `POST /api/plan` | 生成刀路，返回刀路运动段、统计、覆盖率与播放时间轴 |
| `POST /api/export/gcode` | 导出 NC 程序 |
| `POST /api/export/csv` | 导出 CSV 点表（`move_index,pass_index,kind,feed_mm_per_min,point_index,x_mm,y_mm,z_mm`，非切削段 `pass_index` 为 -1） |
| `POST /api/import/dxf` | 读出 DXF 图纸里的 2D 闭合轮廓（请求体是原始 DXF 文本，或 `{"text": "..."}`；`arc_tolerance_mm` 可放在 JSON 里或查询串上） |

`/api/plan` 也接受**导入轮廓**：`{"region": {"shape": "imported", "points": [[x, y], ...]}}`，
点串取自 `/api/import/dxf` 的返回（少于 3 个点、点不是 `[x, y]`、坐标不是有限值都会返回 `400`）。
导入的轮廓不在 `/api/catalog` 里，这是**唯一**不经参数系统构造几何的区域。

```bash
curl http://127.0.0.1:8770/api/catalog

curl -X POST http://127.0.0.1:8770/api/plan \
  -H "Content-Type: application/json" \
  -d '{"tool":{"diameter_mm":6,"length_mm":30},
       "region":{"shape":"circle","parameters":{"diameter_mm":80}},
       "planner":{"id":"raster","parameters":{"mode":"one_way","stepover_mm":6}}}'

curl -X POST http://127.0.0.1:8770/api/export/gcode \
  -H "Content-Type: application/json" -d '{}' -o toolpath.nc

curl -X POST http://127.0.0.1:8770/api/export/csv \
  -H "Content-Type: application/json" -d '{}' -o toolpath.csv
```

参数非法返回 `400`；参数合法但几何上无法加工（例如刀具直径大于区域尺寸）返回 `422`，
响应体中的 `error` 字段给出具体原因。

## 项目结构

```
toolpath_lab/
  core/        领域层：参数声明、刀具、区域、刀路与运动段模型
  planning/    策略层：Planner 基类与注册表、平面多边形几何、栅格刀路、环切刀路、覆盖率分析
  simulation/  时间层：按进给速度把刀路参数化为时间轴
  export/      G-code 与 CSV 导出、自述头部
  importers/   输入格式：最小的 DXF 2D 轮廓读取器
  server/      标准库 HTTP 服务：接口路由、请求校验、能力目录、静态文件
  web/         前端：原生 ES 模块 + three.js（随仓库提供，无打包步骤）
electron/      桌面壳：拉起 Python 后端并承载窗口
examples/      命令行示例与示例插件
tests/         单元测试
docs/          架构与扩展文档
```

依赖方向是单向的：`core` 不依赖其它层，`planning` / `simulation` / `export` / `importers`
只依赖 `core`，`server` 负责组装，`web` 只通过 HTTP 与后端通信，`electron` 只负责窗口。
因此刀路算法可以脱离界面单独运行。详见 [docs/architecture.md](docs/architecture.md)。

## 参数与固定值

**可在界面上调整的参数**（接口里是同名的请求字段）：

| 参数 | 键 | 默认值 | 范围 | 作用范围 |
| --- | --- | --- | --- | --- |
| 安全高度 | `safe_height_mm` | 5 mm | 0–200 | 所有策略（快移时抬到 Z = 0 之上多高；0 = 不抬刀） |
| 快移速度 | `rapid_feed_mm_per_min` | 5000 mm/min | 100–50000 | 所有策略（抬刀 / 横移 / 下刀，计入预计工时） |
| 拐角减速起始角 | `corner_angle_deg` | 0°（关闭） | 0–180 | 所有策略（切削段转角超过它开始降速；0 = 关闭） |
| 拐角最低进给 | `corner_feed_ratio` | 0.35 × | 0.05–1 | 所有策略（180° 折返处降到编程进给的这个比例） |
| 总深度 | `depth_mm` | 0 mm（关闭） | 0–200 | 所有策略（要切到的深度；0 = 只在加工面走一层） |
| 吃刀深度 | `stepdown_mm` | 2 mm | 0.1–50 | 所有策略（每层下刀多少；总深度不是整数倍时最后一层取剩余量） |
| 进刀方式 | `entry_mode` | 直插 | plunge / ramp / helix | 所有策略（下到每层切削面的方式；斜坡与螺旋用切削进给） |
| 斜坡角度 | `ramp_angle_deg` | 10° | 1–45 | 所有策略（斜坡与螺旋的下切角度；越小引入距离越长） |
| 螺旋半径 | `helix_radius_mm` | 1.5 mm | 0.2–20 | 所有策略（螺旋进刀的圆半径；超过刀具贴壁间隙时会被压到间隙以内） |
| 边界处理 | `boundary_mode` | 内缩一个刀具半径 | inset / none | 栅格策略（`none` = 刀心走在轮廓线上，会切出区域一圈） |
| 边界余量 | `stock_allowance_mm` | 0 mm | 0–20 | 栅格策略（在轮廓内侧留一圈余量，`none` 时不生效） |
| 环绕向 | `ring_direction` | 交替 | alternate / climb / conventional | 环切 / 螺旋环切（顺铣 / 逆铣，约定见下；螺旋必须同向，交替时跟最外圈） |
| 目标覆盖率 | `coverage_target` | 99.5 % | 50–100 | 自适应环切（低于它就收窄切宽重算） |
| 工时上限 | `max_time_ratio` | 2 × | 1–10 | 自适应环切（收紧后工时不超过首轮的这么多倍，超出就不采用那一轮） |
| 最多重算 | `max_rounds` | 3 | 0–8 | 自适应环切（再收紧几次；每轮都会多花一点时间） |
| 收紧系数 | `stepover_factor` | 0.7 | 0.3–0.95 | 自适应环切（每轮把切宽乘以它） |
| 切宽下限 | `min_stepover_mm` | 1 mm | 0.2–20 | 自适应环切（再小也不收，否则环数暴涨） |
| 锥度半角 | `taper_angle_deg` | 0°（直壁） | 0–45 | 刀具（刀刃侧面每侧张开的角度；直径指刀尖处，锥面会一起进贴壁间隙） |
| 刀刃长度 | `flute_length_mm` | 0 = 自动（`0.65 × 刀具长度` 与 `6 × 刀具直径` 取小） | 0–300 | 刀具（刀刃以上是刀柄；切深超过刀刃后刀柄进入型腔） |
| 刀柄直径 | `shank_diameter_mm` | 0 = 自动（`1.25 × 刀具直径`） | 0–200 | 刀具（刀柄比刀刃粗时需要型腔留出相应间隙，否则报刀柄碰撞） |

前六项（安全高度、快移速度、拐角减速起始角、拐角最低进给、总深度、吃刀深度）声明在
`toolpath_lab/planning/base.py` 的 `MOTION_PARAMETERS`，由各策略并进自己的 `ParameterSet`，
所以新增策略只要 `+ MOTION_PARAMETERS` 就自动获得；边界两项是栅格策略特有的，环绕向是环切
特有的，最后五项是自适应环切特有的（它在环切参数集上再加这五项）；**最后三行是刀具自身的参数**
（声明在 `toolpath_lab/core/tool.py`，与策略无关，`0` 表示按上面的规则自动取值）。螺旋环切与环切
**共用同一组参数**（它走的就是同一串偏置环，区别只在环与环之间怎么过去）。

**顺铣 / 逆铣怎么算的**：这里按**几何绕向**标注——环切从外往内走，未加工的材料始终在环的
**内侧**，所以在"主轴 M03（从上往下看顺时针）+ 右手刀具"的前提下，**逆时针 = 顺铣**
（接触点的刀刃运动方向与进给同向），顺时针 = 逆铣。换成 M04，或者加工的是外轮廓（材料在刀路
外侧），顺铣与逆铣就要对调。栅格策略没有这个参数：一刀的两侧一侧顺、一侧逆，没有单一答案，
往复本身就是在交替。

**仍然是固定的设计选择**：

| 事项 | 值 | 位置 |
| --- | --- | --- |
| 每刀采样 | 两个端点（加工面是平面，所以一刀两个点）；**区域带岛屿时**按采样步长离散，因为一刀要在离岛一个刀具半径处断开 | `toolpath_lab/planning/raster.py` |
| 岛屿的处理 | 刀心离岛屿 ≥ 刀具半径；轮廓环与岛屿环各自只保留离自己更近的一半（中缝规则），栅格刀路的断开处抬刀快移 | `toolpath_lab/planning/islands.py` |
| 岛屿环的偏置 | `offset_loops` 只支持向内，所以岛屿环由采样外偏置生成（凸角接圆弧、凹角接尖），并按弦高再外让一点，保证折线不啃岛 | `toolpath_lab/planning/islands.py` |
| 材料切除的刀具模型 | 按刀具**截面轮廓**扫掠（球头球面、圆鼻平底+角圆弧、平底/锥度平底）；锥面只参与贴壁间隙 | `toolpath_lab/planning/removal.py` |
| 到面率的容差 | 相邻两刀的**理论脊高**（球头 `R−√(R²−(s/2)²)`），脊为 0 的平底刀因此与旧数字一致 | `toolpath_lab/planning/removal.py` |
| 圆形离散 | 180 段折线逼近（圆与椭圆共用，见 `CURVE_SEGMENTS`） | `toolpath_lab/core/region.py` |
| 工件建模 | 按区域边界多边形挤出，上表面在 Z = 0 | `toolpath_lab/web/js/viewport.js` |
| 环切边界 | 第一环永远内缩一个刀具足迹半径（偏置几何只支持向内） | `toolpath_lab/planning/contour.py` |
| 分层方式 | 每层是同一 XY 路径下移（竖直壁、平底，岛屿由刀路绕开而不是"抬刀跳过"） | `toolpath_lab/planning/stepdown.py` |
| 刀路显示 | 加工面上的折线抬高 0.05 mm 避免 z-fighting；低于加工面的分层刀路保留真实深度，此时工件画成半透明 | `toolpath_lab/web/js/viewport.js` |
| 覆盖率 / 材料切除网格 | 0.5 mm 一格、最多 40 万格（区域大时自动放大），两者共用同一套网格 | `toolpath_lab/planning/coverage.py` |
| 高度图显示网格 | 降采样到 ≤ 4096 格（每格取块内最深值），只影响三维着色，不影响任何体积与比率 | `toolpath_lab/planning/removal.py` |
| 播放联动快照 | 一次扫掠里拍 ≤ **8** 张（各按 **1024** 格降采样、共用完整地面的色标），只在快照变化的帧重建几何 | `toolpath_lab/planning/removal.py` |
| 曲面毛坯的上表面 | 区域可选带 `top_height_mm`（球冠：`Rc = (R²+h²)/(2h)`）；三维用 ≤ **32×32** 格的上表面网格画，区域外为空 | `toolpath_lab/core/region.py` |
| 曲面毛坯仍是 2.5D | 等高分层是恒定 Z，不做随形加工（曲面上方的层切空气）；曲面只改变"料有多少"与显示，不改变刀路 | `toolpath_lab/planning/service.py` |
| 未切除输出上限 | 最多 8 处连通块、800 个矩形（超出只计入总数） | `toolpath_lab/planning/coverage.py` |
| 播放采样上限 | 时间轴最多 4000 个采样点 | `toolpath_lab/server/service.py` |
| 碰撞检查容差 | 0.01 mm：偏置折线近似的噪声不算碰撞（正好贴合时余量按 0 报） | `toolpath_lab/planning/collision.py` |
| 进刀段不裁剪 | 斜坡 / 螺旋按几何长度走，允许伸出区域，只报长度与伸出距离 | `toolpath_lab/planning/entry.py` |
| 螺旋的适用判定 | 与同一形状的环切比覆盖率，掉超过 **2 个百分点** 就回退环切（单面进刀的形状只差接缝那一圈） | `toolpath_lab/planning/spiral.py` |
| 折线化段数封顶 | 单条 `ARC`/`CIRCLE`/`ELLIPSE` 最多 **2048** 段，容差再小也不更细（否则 0.001 mm 容差能要出几万个点），封顶时在提醒里说 | `toolpath_lab/importers/dxf.py` |

再加一个参数的完整做法（声明 → 读取 → 补测试 → 记 CHANGELOG）见 [docs/extending.md](docs/extending.md) §3。

## 扩展

- **新增刀路策略**：继承 `Planner`，声明参数并实现 `plan()`，然后在 `planning/__init__.py`
  里导入一行即可注册。内置的 [contour.py](toolpath_lab/planning/contour.py)（环切）与
  [examples/plugins/contour_planner.py](examples/plugins/contour_planner.py) 放在一起看，
  就是"一个策略需要写什么"的完整例子。
- **新增区域形状**：实现一个返回逆时针边界多边形的 `boundary()`，栅格刀路、环切与三维工件都会
  自动适配——工件就是按这条边界挤出的，环切也靠通用的偏置几何（细颈被吃掉时会分裂成多条环）。
  所以矩形、椭圆、U 形、哑铃形（甚至凹多边形）都没有改刀路或前端代码。
- **新增导出格式**：在 `export/` 中写一个纯函数，并在 HTTP 路由中加一个分支——
  `gcode.py` 与 `csv.py` 就是现成的两个例子。
- 完整说明见 [docs/extending.md](docs/extending.md)，开发约定见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 设计说明

刀路模型采用机械加工中常见的平行扫描线（栅格）与等距轮廓（环切）两种形式，时间轴按各段运动的
进给速度累加，三维交互沿用通用的三维 CAD 操作习惯（左键旋转、中键缩放、右键平移）。
