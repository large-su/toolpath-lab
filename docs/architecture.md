# 架构

## 分层与依赖方向

```
   electron/main.mjs           独立窗口（只负责拉起后端并装窗口）
        │  HTTP / JSON
      server ─────────┐
        │             │
   ┌────┴────┐     export
   │         │        │
planning ── simulation ┘
   │            │
   └──► core ◄──┘
        ▲
        │ 静态文件
      web（原生 ES 模块 + three.js）
```

依赖只有一个方向。`core` 不认识任何其它层，`planning` / `simulation` / `export` / `importers`
只依赖 `core`，`server` 组装全部，`web` 只通过 HTTP 说话，`electron` 只负责窗口。由此得到三个好处：

- 刀路算法可以脱离界面单独跑（`examples/headless_plan.py`）；
- 换传输层（CLI、gRPC、ROS 节点）不需要动算法；
- 把 `core` + `planning` 搬进别的项目不会拖入框架依赖。

## 各层职责

### core —— 领域层

| 模块 | 职责 |
| --- | --- |
| `parameters.py` | `ParameterSpec` / `ParameterSet`：声明式参数（类型、范围、默认值、单位、中文标签、显隐条件、选项的 disabled），同时驱动界面、校验与文档 |
| `tool.py` | 刀具：类型、直径、长度、锥度半角、刀刃长度与刀柄直径，以及由它们推出的**足迹半径**（刀路相对轮廓的偏置量，刀尖平底那份）、**贴壁间隙**（整段切深的外伸半径，锥度刀往上张开也算进去）与**刀刃顶端半径/刀柄半径**（`planning/collision.py` 用的就是这份几何，三维也照它画）；另有**刀具库** `tool_library()`（6 把常用刀，界面「预设」下拉的数据源——它只是把值填进同一组参数的快捷方式，不是第二套配置系统） |
| `region.py` | 区域形状：方形、矩形、圆形、椭圆、U 形、哑铃形、三角形，统一输出逆时针边界多边形（曲线用 180 段折线逼近）；另有**导入轮廓**（`region_from_points`），它刻意不注册进目录——几何来自图纸的点串而不是参数 |
| `path.py` | `Move`（切削/连接/快移 + 进给）与 `Toolpath`（统计、载荷） |
| `registry.py` | 通用能力注册表（区域形状、策略共用） |
| `payload.py` | 请求字典 → 领域对象的拆解工具 |

### planning —— 策略层

- `base.py`：`PlanningContext`（刀具 + 区域 + 参数）与 `Planner` 基类；
  **动作参数**（抬刀高度、快移速度）在这里声明成共用的 `MOTION_PARAMETERS`，
  具体数值由策略参数给出，策略没声明时 `PlanningContext` 退回默认值；
- `geometry2d.py`：平面多边形工具。`scanline_intervals`（直线与多边形求交、偶奇配对）让栅格刀路
  只靠一个几何操作就支持任意形状；`offset_loops`（向内偏置，可能返回多条环）供环切逐圈使用，
  另有 `point_in_polygon` / `distance_to_boundary` / `resample_ring` 等公用工具；
- `raster.py`：往复与单向两种模式；
- `contour.py`：环切（等距轮廓）。偏置几何在 geometry2d.py，这里负责"层 → 环 → 运动段"：
  一层可能有多条环（凹形状细颈被偏置吃掉后分裂），套在里面的环用连接进给过渡，
  同层分裂出的兄弟环抬刀快移，避免在切削深度上横穿未加工区域；
- `coverage.py`：刀路评估。在区域包围盒上布一层网格，逐格判断"格心在区域内 + 被刀具扫过"，
  给出覆盖率、未切除面积与未切除连通块的位置（和策略同层，因为它共用同一套平面几何）；
- `removal.py`：2.5D 材料切除（高度图）。同一套网格换一个判据：每个格子从上表面 Z = 0 起，被任何
  去材料的移动扫过就降到该位置的 Z，于是能读出**到面率**（达到最深地面的格子占比，即按深度的
  覆盖率）、切除体积、剩余余量与完全没碰过的面积。长移动按半格重采样，所以不会把材料算给机床
  没去过的位置。它另外把这份高度图**降采样**成不超过 4096 格的显示网格（每格取块内最深值，
  即"刀在这里到过多深"；格边落在区域包围盒上，区域外的格子留空），给三维视图按切深着色用——
  只有这一层视图数据被降采样，所有体积与比率都按原测量网格算；
- `feeds.py`：拐角减速。按切削段两端顶点的转角把进给线性降下来（转角超过起始角开始降、
  180° 折返降到最低比例），并把折线切成若干段等进给的移动——一条移动只带一个进给，所以
  几何与刀轨数不变、只有进给与工时变。它由规划服务在 `plan()` 之后统一调用，因此**所有策略
  （含第三方插件）都自动获得**，默认关闭。
- `stepdown.py`：分层深度。给出的总深度大于 0 时，把单层刀路按吃刀深度**重复堆叠**：每层是同一
  XY 路径下移（竖直壁、平底、无岛屿，所以平面路径每层相同），到达加工面的点跟着层走，抬刀点
  保持绝对安全高度；`pass_index` 按层偏移，因此刀轨数、切削长度与工时都按层数增长。同样由规划
  服务统一调用，默认关闭。覆盖率只看 XY 距离，所以分层前后数值相同——按深度算覆盖率需要真正的
  材料去除仿真，那是另一件事。
- `entry.py`：进刀段。斜坡/螺旋由 `PlanningContext.entry_moves` 生成（base.py），本模块则**在事后
  从成品刀路上量它**，把长度写进 notes。长度由切深与角度决定：斜坡是一段直线，正好 `切深 / sin(角度)`；
  螺旋沿自身圆周走同一个角度，因此需要 `切深 / (2πr·tan(角度))` 圈，并且**取整圈**（要回到起点正上方
  才能接上第一刀），所以半径越小圈数越多、还可能多走将近一圈。两者都**不裁剪到区域轮廓**，浅角度
  会走出工件，所以说明里同时给出"最长一段有多少伸出区域"。判据是"没有 pass_index 的切削移动"——
  与 CSV 导出的约定一致（`pass_index = -1` 表示不是某一刀）；连续几段算一段，因为拐角减速或插件
  可能把一次下刀切成多段移动。
- `collision.py`：刀柄碰撞检查。把刀具看成两段——刀刃（半径 **随高度变化**：底面平底 `R−Rc`、圆角
  弧到 `R`、再按 `tan(锥度)` 往上张开，高 `flute_mm`）与它上面的刀柄（半径 `shank_radius_mm`，也就是
  三维画的那把刀），在 2.5D 的竖直壁假设下问"刀刃以上的部分能不能进型腔"：切深超过刀刃后刀柄就在
  型腔内，它需要 `刀柄半径` 那么宽的壁边空间，而策略只保证**刀刃**自己的贴壁间隙（最外一圈刀路正好
  压在偏置线上）。因为是锥度刀，每个刀点要的半径不同（取该点切深处的刀刃半径与刀柄半径的较大者），
  于是判据是"逐点：离壁距离 − 该点刀具半径"的最小值（`margin_mm`），负值即干涉；`最深切深 > 刀具长度`
  则是"夹头会伸进工件"。**锥面自己永远不会碰撞**：偏置量按整段切深算，本来就 ≥ 任一层的刀刃半径，
  所以实测的余量在锥度刀上正是"偏置量 − 该层刀刃半径"，只有刀柄（偏置几何不知道它）或刀太短才会报。
  容差 0.01 mm：偏置几何的折线近似让"正好贴合"的余量落到微米级，不能把这点噪声报成碰撞。
  两者都只给**提醒**不给错误（刀刃、刀柄、锥度是调用方对真实刀具的估计），结果同时随响应给出
  （`holder` 块）供脚本与界面读。两处刻意不查：**进刀段**（斜坡/螺旋允许走出区域，长度由「刀路说明」
  负责；走出区域后碰到材料的是刀刃而不是刀柄）与**区域外的点**（那不在型腔里）。距离用
  `geometry2d.distance_to_boundary`，逐点向量化算。
- `adaptive.py`：自适应环切。继承环切策略、只重写 plan()：先用请求的切宽算一遍、量一下覆盖率，
  没到目标就按系数收窄重算，最后返回覆盖率与工时都合适的那一次。停止条件有三个层次：
  达标就停；覆盖率**确实提升**才继续（覆盖率并非切宽越小越高，到了刀具几何的极限再收窄只会
  白走刀）；超出「工时上限」（收窄靠多走几圈，代价是线性的）的那一轮不采用。到不了目标时用
  warnings 说明是工时上限挡住了还是已经到几何极限，并把每一轮的切宽/覆盖率/环数/切削长度/工时
  写进 notes（「刀路说明」里直接读）。它演示了"加一个策略就是一个类"，连刀路逻辑都是复用的。

### simulation —— 时间层

`build_timeline` 把每段运动按自己的进给速度换算成时间（t = 弧长 / 进给），在弧长上重采样并限制
总采样数（默认 4000），同时保留每段边界，所以播放不会跨段插值。载荷里 `times` / `positions`
是逐采样数组，`kind_runs` / `move_runs` 是游程编码。

### export / importers / server / web / electron

- `export/gcode.py`：G21 / G90 / G17 + G0 / G1 带 F 的最常见 ISO 子集；
- `export/csv.py`：一个刀点一行的点表（纯 ASCII，`move_index,pass_index,kind,feed,…,x,y,z`）；
- `importers/dxf.py`：最小的 DXF 2D 轮廓读取器（`LWPOLYLINE`、`POLYLINE` 与首尾相连的 `LINE`；
  圆弧与圆**不猜**，如实列进 `skipped` 并给出中文提醒）。纯函数：吃文本、吐轮廓，读写文件留给
  调用方；它只依赖 `core`，与 `export/` 对称。
- `server`：标准库 `ThreadingHTTPServer`。`schema.py` 是唯一的请求校验入口，`service.py` 组装响应，
  `catalog.py` 生成能力目录，`app.py` 只做路由与错误码映射（400 参数错误 / 422 几何不可行 / 404 / 405）；
  静态文件只从 `web/` 提供并做了路径穿越防护；
  - `/api/import/dxf` 是无状态的：请求体是原始 DXF 文本（或 `{"text": "..."}`），返回轮廓的点串、
    是否闭合、层名与跳过项，**不落任何盘**；调用方再把选中的点串发给 `/api/plan`。
  - `schema.py` 里**唯一**一条不走参数系统的分支是 `region.shape == "imported"`：点串交给
    `region_from_points`（`ParameterSpec` 没有列表类型），规范化后的点串再回显进 `request`。
    因为点串可能很长，`ImportedOutlineRegion` 在响应里只报 `point_count`，导出头部走
    `header_text()` 写成 `imported - N points`——点串在响应里已经出现两次（请求回显 + 边界多边形）。
- `web`：`panel.js` 依据目录生成控件（显示开关也在里面），`viewport.js` 负责 three.js 场景与相机
  （工件按区域边界多边形挤出，未切除区域按后端给的矩形叠一层半透明警示色，高度图按后端给的显示
  网格画成按切深着色的地面，所以新增形状不用改前端），
  `playback.js` 是纯逻辑的时间插值器，`main.js` 负责串联；导入轮廓是唯一一处界面自己加的下拉项
  （导入成功后才有，见 `panel.js` 的 `IMPORTED_ID`）；
- `electron/main.mjs`：挑一个空闲端口 → 拉起 `python -m toolpath_lab` → 轮询 `/api/health` →
  装进原生窗口；关窗时结束后端。前端是普通静态文件，所以不需要打包器。

## 关键算法

### 栅格刀路

1. 把区域轮廓旋转到"走刀坐标系"：u 沿走刀方向，v 垂直于它；
2. 在 v 方向按切宽布刀，两端各内缩一个刀具足迹半径（保证刀不会切出区域）；
3. 每条刀线用 `scanline_intervals` 求交，得到它在区域内部的区间（方形是整条，圆形是一条弦，
   凹形状可以是多段）；
4. 区间两端就是这一刀的起点和终点——一刀两个点，因为加工面是平面；
5. 往复模式奇数刀反向、刀间直接连过去；单向模式每刀同向、刀间抬到安全面再回来；
   首尾补"下刀"和"抬刀"。

### 环切刀路

偏置本身做了三处**可证明不改结果**的剪枝：两两求交按包围盒分桶（相交的线段包围盒必然重叠，
所以不会漏）、判"到边界距离 ≈ 偏置量"时先用支撑直线筛边（点到线段的距离 ≥ 点到其直线的距离，
所以最近边一定在候选里）、切分前先筛掉不合法的交点（合法性只在合法交点处变化）。大偏置量下
平移线段会比偏置周长还长、互相大量相交（直径 80 的圆、偏置 33 时有 1800 个交点、3780 个子段，
其中只有 180 个合法），这三处剪枝让圆形环切一次规划从 0.76 s 降到 0.22 s，输出逐位不变。

1. 第一层把轮廓向内偏置一个**刀具足迹半径**（保证刀不切出区域），之后每层再偏置一个切宽；
2. 偏置到没有任何环为止，因此层数是切宽与区域尺寸的自然结果；
3. **一层可能有多条环**：凹形状的细颈被偏置吃掉后形状会分裂成几块，每块单独加工。偏置本身
   （`offset_loops`）分四步：把每条边向内平移并延长到斜接点、给每个凹角补一段圆弧、在所有
   交点处切分、只保留"到边界距离 ≈ 偏置量"的子段，最后按"转角最小"接成闭环；
4. 每环按采样步长等弧长离散成闭合折线——环是曲线，必须有采样步长，这与栅格的"一刀两个点"不同；
5. 相邻环绕行方向交替（顺铣/逆铣交替）；环间过渡分两种——套在里面的环直接连接进给走过去，
   同层分裂出的兄弟环抬刀到安全面再快移，因为横穿细颈会啃到材料；
6. 已知限制：只有直线连接、没有引入 / 引出圆弧；比刀具还窄的特征（尖鳍、细颈一旦被偏置吃掉）
   会整块消失，也就是那一小块切不到——这正是覆盖率分析要标出来的东西。

### 覆盖率分析

刀路生成完之后再问一句"切干净了吗"：在区域包围盒上布一层网格（默认 0.5 mm，区域大时按
`MAX_CELLS` 自动放大），逐格判断

1. 格心在不在区域内——逐行用扫描线区间标记，和栅格刀路同一套几何；
2. 格心到任意一段**去材料**的运动（切削 / 连接，快移不算）的距离是否 ≤ 刀具足迹半径
   ——每段只处理它外扩一个半径后的那一小块网格，所以开销与刀路长度成正比而不是乘积。

未切除的格子按行切成游程再用并查集合并，就得到"漏了几处、最大一处多大、大概在哪里"；
另外把未切除格子再**贪心合并成少量矩形**随响应返回，前端直接画成四边形叠在工件上，
一眼就能看出哪块没切到。圆刀在方形尖角、曲线区域的折线逼近处总会留一点点，那是几何必然，
所以提醒阈值默认 2%；真正要提醒的是成片漏切（切宽大于刀具直径、环切步距太大剩中心）。

这套分析还接回了规划：`adaptive.py` 用覆盖率当目标函数，自动把切宽收窄到达标或收窄到不划算
为止（见上）。两个停止条件值得记一笔——覆盖率不是切宽越小越高，**到极限之后继续收窄只会
白走刀**；而收窄的代价（工时）是线性的，**多花一倍时间只换 0.02 个点就不划算**。所以循环只在
覆盖率确实提升、且工时仍在「工时上限」内时才继续，并把每轮的实测值写进 notes 供人判断。

### 时间参数化

每段运动携带自己的进给速度，累计时间就是各段"弧长 / 进给"之和，因此快移段与切削段对"预计工时"
的贡献不同。播放时在时间轴上二分查找 + 线性插值；采样下标同时用于"已走轨迹"的绘制范围
（`setDrawRange`），不需要额外几何。

## 想动手改的时候

- 想加**参数**：在对应能力的 `ParameterSet` 里加一行 `spec(...)`，界面与校验自动跟上；
  所有策略都用得到的动作参数并进 `MOTION_PARAMETERS`，只有单个策略需要的写在它自己的 set 里；
- 想加**形状**：写一个 `boundary()` 返回逆时针多边形；进接口与导出头部的描述默认由
  `to_params()` 生成，若它不适合直接打印（例如一串点），覆写 `header_text()` 给一句简短的写法；
- 想加**策略**：继承 `Planner` 并注册，见 extending.md；
- 想加**曲面 / 三维区域**：给区域加高度场、给 `Move` 加刀轴字段，再在策略里逐点采样；
- 想加**导出格式**：在 `export/` 写一个纯函数，在 `server/app.py` 加一个分支。
